# Maintenance plan/order/material feature contract
Scope approved by user: recurring maintenance schedules, repair orders, material cost ledger in VND; NO stock deduction, NO auth contract changes. No commit/push/deploy/dependency changes. Preserve dirty tree.

API base /api/v1/maintenance; ALL reads and writes require existing UAV_MANAGE (UAV_READ is held by customers and must NOT expose prices). Standard direct JSON, existing PageResponse.content pagination.

Schedule: id,uavId,uavSerialNumber,title,intervalDays,nextDueDate,lastCompletedDate(nullable),active,version,dueStatus (UPCOMING/DUE/OVERDUE/PAUSED). Dates YYYY-MM-DD, business calendar Asia/Ho_Chi_Minh. Multiple schedules per UAV permitted. Due is advisory, no auto grounding/job/email.
GET /schedules?uavId=&dueStatus=&page=0&size=20; POST /schedules {uavId,title,intervalDays,nextDueDate}; PUT /schedules/{id} {expectedVersion,title,intervalDays,nextDueDate,active}; no deletion (pause instead). interval1..3650, title1..160. Mutation blocked while linked OPEN/IN_PROGRESS order exists. nextDue after linked completed repair = completion business date + current intervalDays; cancellation never advances schedule.

Order response: id,uavId,uavSerialNumber,scheduleId(nullable),title,description,plannedDate,technicianName,status (OPEN/IN_PROGRESS/COMPLETED/CANCELLED),version,createdAt,startedAt,completedAt,cancelledAt,inspectionNotes,cancelReason,materials:[{id,name,unit,quantity,unitPrice,lineTotal}],totalMaterialCost,currency:'VND'. Return monetary/quantity decimal fields as strings; calculated on server. Title1..160, description<=2000, technicianName1..120, required plannedDate. Completion/cancel notes1..1000.
GET /orders?uavId=&status=&page=0&size=20; GET /orders/{id}; POST /orders {uavId,scheduleId?,title,description,plannedDate,technicianName}; PUT /orders/{id} {expectedVersion,title,description,plannedDate,technicianName}; POST /orders/{id}/start {expectedVersion}; PUT /orders/{id}/materials {expectedVersion,items:[{name,unit,quantity,unitPrice}]}; POST /orders/{id}/complete {expectedVersion,inspectionNotes,inspectionPassed:true}; POST /orders/{id}/cancel {expectedVersion,reason}.
Material name1..160, unit1..30, qty>0 <=10000 at most3decimals; price>=0 <=1e9 integerVND; max100lines. BigDecimal exact, lineTotal HALF_UP to integer VND, total sum rounded lineTotals. Zero lines allowed. Never accept client totals. Edits/materials only OPEN/IN_PROGRESS; terminal immutable. All updates expectedVersion (nonnegative) mandatory, stale409 code MAINTENANCE_VERSION_CHANGED. Flush before returning newversion.

One OPEN/IN_PROGRESS order per UAV, including competing requests. Creating OPEN allowed when UAVbusy (planning) but does not alter UAV. Starting requires idle/noactive mission, AVAILABLE/INACTIVE/MAINTENANCE and moves/adopts MAINTENANCE. No mission row lock after UAV lock. Completion requires IN_PROGRESS, inspectionPassed and notes, noactive mission, makes orderCOMPLETED then UAVAVAILABLE atomically, advances linked schedule once. OPEN cancellation no UAV change; IN_PROGRESS cancellation retains MAINTENANCE and recorded costs. Legacy manual status/station operations must not bypass an IN_PROGRESS order. Explicit reason/errors explain active repair must be closed first. OPEN order does not reserve UAV availability.

Lock UAV first then order/schedule; refresh locked entities; bounded short audit records for all writes share transaction, actor/time captured. Add Flyway V3 only; no editsV1/V2.
