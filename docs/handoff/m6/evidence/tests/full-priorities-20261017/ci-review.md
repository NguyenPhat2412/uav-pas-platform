## Actionable findings

1. **[P2] Fail the complete backend gate when tests are skipped.** `backend/infra/ci/backend_tests.py:17` returns zero whenever Maven succeeds and the aggregate test count is nonzero, even when the parsed `skipped` count is positive. A missing integration prerequisite or an assumption abort can therefore produce a green “complete backend” job without executing all PostgreSQL/MinIO coverage. The wrapper already collects skipped counts at lines 8–11, but does not enforce them. Require zero skipped tests as well as a nonempty, successful suite, and record a safe failure reason in `result.json`. This is the brief's complete/no-skip backend requirement, not a request to rerun the existing expensive suite during this review.

2. **[P2] Preserve ownership evidence until fallback cleanup completes.** `backend/infra/ci/run.py:302` removes the entire private directory whenever `GITHUB_ACTIONS=true`, including when a `compose down` failure has set `cleanup=False` at lines 294–298. The workflow's fallback at `.github/workflows/m1-foundation.yml:157` runs its label-scoped container/volume removal only when that directory still contains `owns-resources`. Consequently, exactly the cleanup failure the fallback should recover from deletes the prerequisite marker and leaves owned resources behind. Leave ownership evidence available on failed cleanup (or move it outside the directory being removed) and let the workflow remove it only after the fallback has attempted cleanup. Keep private logs/backups excluded from artifacts.
