## User-visible changes

- Customer and Operations share mission status/service/priority labels, metadata layout, guidance for the current stage, file cards and compact history. The four newest events appear first; “Xem toàn bộ … sự kiện” reveals the complete ordered history. Authored completion, rejection and conflict notes remain visible.
- Operations controls require both matching permissions and lifecycle stage. Start/complete require the assigned operator. Resource selectors respect read and assignment permissions; unavailable resources and already-bound UAV/operator assignments are not offered as actionable choices. Pending requests disable buttons and file input. Failed actions reload mission state.
- Closed missions hide mutation controls, including acceptance, conflict and upload. **This is a frontend affordance rule, not new backend enforcement:** the existing backend conflict/media endpoints are unchanged. Authorization remains server-side.
- Cancellation asks for confirmation; rejection/conflict require a nonblank reason; completion supports a note. No new endpoint or auth payload was introduced. Operations uploaded results now use the existing `OUTPUT` media role (videos retain `FLIGHT_DATA`) instead of labelling result files as `INPUT`.
- Resource names are shown from permitted resource lists; a labelled identifier remains the fallback when a name is unavailable. The app does not fetch user lists without `USER_READ`.
- Three real section links replace six misleading pseudo-tabs. Each link reaches a rendered section.
- Customer mobile navigation has four persistent, labelled destinations with bottom clearance. Mission lists adapt to stacked rows. Operations/Admin mobile navigation supports Escape, focus containment, background inertness and focus return after closing. Focus return was corrected after a real browser assertion exposed focusing while the background was still inert.
- Admin audit has Vietnamese column/action/status labels, shorter readable timestamps, and a filter explicitly limited to the **current page**. Mobile records stack into labelled fields. User/role/permission display copy is translated without changing underlying values or permission semantics. Unknown codes and user-authored data remain intact.
- A real production-build 404 was found: Operations login linked to an absent `/register` route. That dead link is replaced with instructions to contact an administrator. Login behavior is unchanged.
