## Query and evidence boundaries

- AuthContext uses `[session, userId or anonymous, permissions]` for permission polling; it clears/cancels the QueryClient on account changes and permission changes.
- Access Control uses `[session, scope, access, ...]` for users, permission catalog, templates and selected-user overrides. Mutations invalidate access, target-user permission, audit and dashboard feature keys.
- Operations hooks use user-scoped `feature`, `list`, `detail`, and `history` keys. Generic collection hooks back stations, UAVs, equipment, media and audit panels. EquipmentPanel currently uses `useCollection(equipment)` plus `useInventoryHistory(0)`; no active `useCollection(movements)` caller was found.
- Mission list/operator/admin pages use `useMissions` with `[missions, list, filters]`, but the key is not user-scoped. Mission detail and mission create/dashboard reads still use local state and `useEffect`/`Promise.allSettled`; mission mutations invalidate `[missions]`.
- Backend-only rows use `—` for the query mapping. Missing routes or services are written as `—`; they are not inferred from UI labels.
- Evidence paths are relative to `docs/handoff/final/` unless prefixed by `../` in the existing reports. Browser traces cover selected operations, station drawer, access denial and the CSS UAV viewer only.
